# Brand Brief

The document upstream of `DESIGN.md`. Positioning and tone first — visual rules should
follow from what the product actually is, not the other way around.

## Fields worth capturing

| Field | Question it answers |
|---|---|
| What the product does | One or two sentences, plain language |
| Audience | Who actually uses this, and what they already expect from similar tools |
| Positioning | What it's competing with or replacing, and why someone picks it |
| Tone | How it talks to the user — three adjectives, not a paragraph |
| Identity anchors | Existing name, logo, colors, or type already committed to (don't relitigate what's already decided) |
| Non-goals | What this product deliberately is *not* — as useful as what it is |

Keep it short. A brand brief that takes ten minutes to write and is actually read beats a
thorough one that gets skipped. If one already exists for the product, read it before
proposing anything — don't re-derive positioning that's already been decided.

## Turning research into a brief

If there's a research vault (Obsidian or similar) behind this, the brief is a distillation
of it, not a pointer to it. Pull the specific conclusions that affect tone/identity into
the brief itself; name the specific source notes if useful for traceability, but don't
make `DESIGN.md` authorship depend on reading the whole vault later.
